# Session analysis scripts

## Next-Sunday workflow

On Sunday, run this from repository root. Next run example:

```sh
python3 scripts/session_analysis.py --week-ending 2026-08-02
```

For later weeks, replace date with that Sunday's date:

```sh
python3 scripts/session_analysis.py --week-ending YYYY-MM-DD
```

`--week-ending` must be Sunday. It analyzes prior Sunday at 00:00 through supplied Sunday at 00:00, exclusive, in `America/New_York` by default. Use named explicit bounds when needed:

```sh
python3 scripts/session_analysis.py --start YYYY-MM-DD --end YYYY-MM-DD
```

`--end` stays exclusive. Other useful switches: `--timezone IANA_NAME`, `--root PATH`, `--output-root PATH`, `--batches N`, and opt-in `--overwrite`. A custom `--output-root` is **not** covered by this repository's ignore rule; tool prints warning, and location must stay private and independently ignored.

## Outputs

Default output is local ignored directory:

```text
session_analysis/<start-date>--<inclusive-end-date>/
├── inventory/session-inventory.json
├── inventory/failure-candidates.jsonl
├── inventory/batch-NN.json
└── analysis/quantitative-baseline.md
```

Inventory includes parent sessions with timestamped activity in window, including activity found in nested `session.jsonl` runs. It also records `complete`, `scanIssueCount`, and per-source `scanIssues`; any unreadable or malformed source writes incomplete inventory and makes command exit nonzero. Batch manifests use source-byte balancing for review distribution.

## Agent review workflow

1. Run script once and freeze generated inventory before source sessions grow.
2. Record top-level session, nested-run, candidate, token, and cost totals from inventory.
3. Review each balanced `batch-NN.json`. Count top-level sessions once; treat nested runs as evidence, not separate user sessions.
4. Read full local context around candidates. Distinguish real failures from expected-red tests, diagnostic probes, quoted error text, and recovered provider retries.
5. Classify parent outcomes as `complete`, `partial`, `failed`, or `aborted`. Keep genuinely ambiguous aborts separate.
6. Deduplicate retries and repeated symptoms under one root problem inside parent workflow. Preserve independent impacts across separate parents.
7. Write dated local ledger, executive summary, and ranked recommendations under same ignored analysis directory. Include evidence limits and any manual judgments.
8. Verify every inventoried parent and nested source received coverage before calling audit complete.

Do not let broad reviewers read every log at once. Assign bounded batches, exact source paths, decision questions, and evidence-sufficient stop rule. Persist reviewer reports inside dated ignored directory.

## Privacy and review limits

**Do not commit, publish, or paste `session_analysis/` output.** [ref:private_session_analysis] It can contain local paths, session IDs, CWDs, usage data, and short redacted diagnostic snippets. Default directory is ignored, but ignore rules do not make copied output safe. Any custom `--output-root` is outside that repository ignore boundary; keep it private and add an independent ignore rule before use.

Failure candidates and baseline are triage inputs, not root-cause findings. Redaction is best-effort pattern matching; inspect local source logs under normal privacy controls. Qualitative conclusions need batch review and original context before changing agent settings or workflow.

Existing dated destination refuses mixed snapshots. Pass `--overwrite` only to replace files generated by this script. Script clones dated directory into private staging, replaces generated subset there, then swaps complete directory into place with rollback on promotion failure. Manual reviewer artifacts and other unrelated files stay untouched.
